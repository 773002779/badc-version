# PART-07 兼容（非标）流水线语义设计

> 需求出处：《需求规格说明书》§9「兼容」行（`docs/requirements/发版流水线-需求规格说明书.md:901`）与
> :694「兼容流水线仅回滚镜像、代码自管」、:410「分支模式标准/兼容」；未实现清单 §2 PART-07 的验收口径：
> 「明确语义：兼容模式跳过构建节点的合并校验并提示；否则字段删除，避免『存而不用』」。

## 1. 语义裁决（本切片确定）

- `deploy_unit.branch_mode` 的两个值：
  - `STANDARD`（默认）：标准流水线——每个发布窗口一条发布分支，平台全权代理构建/部署/回滚。
  - `COMPATIBLE`（兼容/非标）：**该单元的代码变更由团队自行管理，平台只负责镜像投递**。具体口径与需求 §9 一致：
    1. 回滚**只切镜像**（本就是一期的统一行为 C17），兼容单元在回滚入口与发布页显式提示「代码需自行 revert」；
    2. 平台**不做**构建节点的合并校验（一期本来就没有合并校验——需求原文的「跳过合并校验并提示」在一期代码里
       无可跳过之物，因此语义收敛为**提示**而非行为差异）；不阻塞、不额外校验，`branch_mode` 不进任何流水线判定。
- `framework_template`：纯描述字段（构建模板的占位记录），一期无消费者、不校验取值；保留展示，二期自研构建
  （FR-I-04）时才有语义。
- **不删除字段**：字段已被单元列表/详情展示与创建编辑表单消费，删除是一次破坏性迁移；按上述语义「存而有释」。

## 2. 实现（纯前端 + 文档，无后端改动、无迁移）

- 发布内容页：非 LIB 发布读 `getUnit(detail.unitId)`（失败容忍，与 LIB 分支同款 best-effort）；
  `unit.branchMode === 'COMPATIBLE'` 时在发布页头部渲染提示横幅（info alert）：
  「兼容模式单元：平台只投递镜像，代码变更与回退由团队在 CODING 侧自行管理；回滚仅切镜像。」
- 回滚抽屉（`RollbackDialog`）：打开时读 unit（best-effort），兼容单元在抽屉内追加同款提示，回滚操作不阻断。
- 按钮可用性、流水线行为、门禁与审计：**一概不变**（`branch_mode` 不参与任何后端判定，见 §1）。

## 3. 测试口径

1. 无后端改动：既有全量测试不动（`mvn -o test` 仍 1038 绿，仅回归确认）。
2. 前端：`npm run build` 绿；探针 `scripts/verify-p7-ui.mjs`（复用 `demo-redeploy.sql` 种子 + 探针内把
   `deploy_unit` 临时置 `COMPATIBLE`、结束还原 `STANDARD`）：双主题断言发布页横幅与回滚抽屉提示出现、
   STANDARD 单元无横幅、0 console error；截图 `compatible-{light,dark}.png`。
