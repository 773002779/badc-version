# CODING 对接配置 — 设计（短设计，2026-11-22）

## 1. 为什么做

P1/P2 的所有引擎能力（构建、部署、任务候选、门禁检查）都依赖一条 CODING 连接，但这条连接
只能手工改库：`coding_conn` 表、AES-GCM 加密、`CodingConnAppService` 都在，**没有任何 HTTP
接口**；`CodingProbe` 只有接口没有实现，点「测试连接」必然得到 `ENGINE_UNAVAILABLE`。
两个页面（设置页、单元详情）直接写着「暂无管理接口」。

结果：拿到真实租户的人无法在页面上完成对接，也无法判断失败是地址、凭证还是项目配错。

## 2. 目标 / 非目标

**目标**

1. 平台管理员在设置页完成：填写地址 / 团队 / 默认项目 / 凭证 → 保存 → 测试连接。
2. 测试连接给出可读结论与任务数量（构建 N、部署 M），并记录上次校验时间与结果。
3. 凭证只显 `tok-***`；轮换时留空即保留原值；明文永不落库、落日志、返回。
4. 系统详情页可编辑「CODING 项目」；为空时任务查询继承连接的默认项目。

**非目标**

- 每系统一套连接（`scope=SUBSYSTEM`）：表与领域已支持，但引擎只解析 GLOBAL，UI 本期不暴露。
- 端点模板 / 状态词表在线编辑：仍在 `coding-endpoints.yml`，改配置需要重启与评审。
- 单元级「绑定校验」（任务存在、项目一致）：另一件事，排在后面。

## 3. 方案与取舍

- **A（采纳）设置页「CODING 对接」**：全局连接表单 + 测试 + 子系统项目行内编辑。不动引擎 SPI，
  现有任务选择与构建立刻可用。
- **B = A + 每系统连接**：要把子系统上下文带进引擎（SPI 或按 unit 每次解析），多租户隔离更像
  P3 的活。
- **C = A + 端点在线编辑**：把「改接口契约」变成页面操作，且与 yml 双源。

## 4. 决定的细节

### 4.1 API（`/api/v1/coding`，全部要求 `setting:manage`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/coding/conn` | 全局连接；未配置时 `configured:false`，不报错 |
| PUT | `/coding/conn` | 保存；`token` 为空/缺省 = 保留原凭证，首次配置时必填 |
| POST | `/coding/conn/test` | 测试连接；body 可选（草稿测试），缺省字段回落到已存配置 |

响应包含 `baseUrl / team / project / tokenHint / updatedAt / lastProbeAt / lastProbeOk /
lastProbeMessage`，不含凭证明文。

### 4.2 测试连接做什么

用给定连接调用 `job.list`（BUILD 再 DEPLOY），一次调用同时证明：地址可达、凭证有效、项目可达。
返回 `ok / status / message / buildJobs / deployJobs / at / persisted`。任一次调用抛
`EngineException` 即 `FAILED`，消息原样给操作人（引擎已做 token 脱敏）。项目为空直接 `FAILED`，不发请求。

**何时算「上次校验」。** 只有被测值**恰好等于已保存连接**时才写 `last_probe_*`
（表单未改动 → 回落到已保存值 → 命中）；改了地址或凭证再测属草稿测试，不写库，返回
`persisted:false`，页面据此说明「草稿测试，结果不写入配置」。这比让调用方传一个 `persist` 标志更诚实。

不把失败原因硬拆成「地址 / 凭证 / 项目」三行：引擎只给一句话（`HTTP 401`、`连接超时`、
`不是数组`），拆行会变成猜。页面展示这条消息 + 任务数量，操作人自己就能定位。

### 4.3 凭证与项目

- 加密不变（`CredentialCipher`，AES-GCM，`CODING_CRED_KEY`）。
- 保存时 token 为空 → 复用已存密文；无已存行 → `40000 凭证不能为空`。
- 连接的 `project` 是**默认项目**；`subsystem.coding_project` 优先，为空时继承默认项目。
  两处都空 → `40000`，消息点名系统。

### 4.4 持久化

`V20__coding_probe.sql` 给 `coding_conn` 加 `last_probe_at / last_probe_ok /
last_probe_message`。只记最近一次，供页面显示与 P3 的失效告警复用；草稿测试不写库（见 4.2）。

### 4.5 页面

设置页新增整块「CODING 对接」（非管理员显示需要 `setting:manage`）：状态行、四个字段、
保存 / 测试连接、结论条（成功显示构建/部署任务数，失败显示引擎消息）、上次校验时间。
系统详情「CODING 项目」改为可编辑，并提示「为空时继承连接的默认项目」。
