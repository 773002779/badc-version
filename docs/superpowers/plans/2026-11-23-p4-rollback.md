## 任务

### Task 1（后端，端到端）：回滚数据、服务、执行与完成

**交付**
1. `V25__rollback.sql`：`rollback_record` 表；`release_order.executed_by`。
2. 领域/仓储：`RollbackRecord`（状态 RUNNING/SUCCESS/FAILED）、PO、Mapper（版本清单 SQL、按实例查、分页）。
3. `PipelineFactory.createRollback(...)`：只有 `PROD_DEPLOY` 节点、反向批次号、`image_digest=目标`、`trigger=ROLLBACK`。
4. `ProdDeployNodeHandler`：`ROLLBACK` 实例跳过边界探针（封板/门禁/复核），批次机制复用。
5. `PipelineEventListener`：`ROLLBACK` 实例的 `PROD_DEPLOY` 完成不映射 `PROD_OK`。
6. `RollbackCompletionService`：`InstanceFinishedEvent` → DONE/FAILED 收敛记录；DONE 且来源变更项仍 DONE → `ROLLED_BACK` + 发布单同步；否则只记成功。
7. `RollbackService`：`versions`、`execute`（校验→版本→锁→事务建记录/实例→bind→advance）、`page`、`detail`。
8. `RollbackController` + `RollbackDtos`：四个接口；`ExecuteProdService` 写 `executed_by`。
9. 权限：versions/detail 登录+单元范围；execute `rollback:execute`；page 按数据范围过滤。

**验收（测试）**
- 版本清单：0/1/11+ 条、同 digest 合并、排除 ROLLBACK 实例、当前=最新。
- 执行前置：40000（目标不在历史/等于当前/原因空/单元不存在）、40001（无成功记录）、40006（锁）、40009（权限/范围）、40011（缺生产配置）。
- 实例：单节点；反向批次（原 1,2,3 → 新 3,2,1，首个触发原 3）；digest=目标。
- 跳过边界：封板生效时回滚实例照常推进，响应带 `freezeWarning`。
- 完成：DONE→SUCCESS+`ROLLED_BACK`+发布单同步；来源非 DONE→只记成功；FAILED→记录 FAILED、变更项不变；不产生 `PROD_OK` 的 item failure 行。
- 全量 `mvn -o test` 绿；提交 `feat: P4 rollback ...`。

## 纪律

- 先失败测试再实现；每任务独立提交；`mvn -o test` 全绿才提交。
- 不引入新依赖；SQL 注释 ASCII；web 层不得依赖 domain 枚举；控制器测试不放 `..web..` 包。
- 后端跑在 :8080 时不要 `mvn verify`；`mvn -o test` 可用（测试库 `release_pipeline_test`）。
