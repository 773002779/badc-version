## Task 1 — 后端：表、服务、查询/导出、接线、测试

1. `V27__audit.sql`（设计 §2，英文 DDL）。
2. domain：`AuditAction`（含中文名与对象类型）、`AuditObjectType`；web 不 import。
3. infra：`AuditLogPO`、`AuditLogMapper`（insert、count/select 带范围、export 查询）。
4. application：`AuditService`（`REQUIRES_NEW` + 吞异常）、`AuditQueryService`（分页/导出 CSV，
   `ScopeGuard` 过滤，unitId 便捷筛选）、`AuditCommand` / `AuditView`；`TraceId` 从 MDC 取。
5. web：`AuditController`（`GET /audit`、`GET /audit/export`，导出用 `ResponseEntity<byte[]>` +
   `Content-Disposition`）、`AuditDtos`（字符串，无枚举 import）。
6. 接线（设计 §1）：`PublishAppService.publish`、`SubmitProdService.submit`、
   `ExecuteProdService.execute`、`RerunAppService.rerun`、`ReleaseApprovalService.approve/reject`、
   `GateService.passTest/failTest/revokeTest`、`GateCheckService.refresh`、
   `GateWaiverService.request/approve/reject`、`FreezeService.create/release/expire`、
   `RollbackService.execute`、`CodingConnAppService.save`、`NotificationSettingService.save`、
   `WindowService.save`、`SubsystemAppService`/`UnitAppService`/`TaskAppService` 的增改。
   每个动作给「变化的字段」而非整行；系统/单元 id 能取到就填，取不到留空。
7. 测试 `server/src/test/java/com/sf/release/audit/`（12+ 个）：设计 §6 全条；不走 `..web..` 包。

硬约束：审计失败不得影响业务；不要在业务事务里做重查询；导出上限 5000；全量测试绿。
